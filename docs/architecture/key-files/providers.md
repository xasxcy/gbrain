- `src/core/embedding-readiness.ts` — bounded source-aware recovery through canonical projection snapshots, queued intent, preparation and guarded installation. Global readiness remains archive-visible. Plain stale repair selects active sources for recovery and separately reports archived stranded work, so live pages can progress without pretending the whole brain completed. `countArchivedEmbeddingWork` classifies archived NULL vectors, non-NULL hash drift, signature work, contentful chunkless pages and, for migration, pending projections before authorization. Repair queues and snapshots require a live source under the existing source-before-page guard; unsupported pages remain blocked, never revision-stamped. The invalidation SQL additionally excludes unsealed projections. #6223: repair walks a keyset cursor (each candidate once per call, ending on a short batch) over Markdown, code and segmented pages only (#6803), so image pages stay counted as blocked and are never queued or re-stamped (a `rebuild_failed` image row keeps its reason); its blocked message names `gbrain projections drain` for the importer-attested ones and `gbrain doctor --only text_projection_readiness --json` for the class counts; `listPendingProjectionPages` lists the first blocked pages and `reportBlockedProjections` writes the CLI's failure sample. `embed --stale` and `embedStaleForSource` no longer stop when pages stay blocked: the guarded drain skips their unsealed snapshots (the CLI counts their chunks as failures and names them with `gbrain embed --stale --images`; the source drain adds them to `blocked` and stays incomplete).
- `src/core/embedding-migration-retention.ts` — fail-closed retained-vector rebuildability check shared by migration preflight, direct apply, schema transition, pinned-column repair and invalidation/config transactions. Transaction-local SHARE locks freeze source/page/vector/withdrawal/config eligibility during the census and mutation. Sealed importer text chunks can be embedded and oversized chunks healed without regenerating their source projection; unsealed unsupported media still refuses. Width changes protect archived, skipped, deleted and unrebuildable retained page vectors; same-width checks match the shared false-stamp predicate, signature gate and current-space test. Archived pending work, including same-target content drift, metadata-only restamping, NULL vectors and chunkless pages, refuses before authorization or provider work; correct target-stamped archived vectors, including grandfathered NULL hashes, are retained controls. Companion retention checks follow actual schema/pinned-width changes and the same-target persisted migration marker; the guard returns the locked companion-clear decision consumed by the writer, ignoring a different target's completed-clear flag. Schema-only work leaves takes untouched. Existing fact eligibility and deliberate expiry/supersession/audit/withdrawal policy remain unchanged. Unknown registry, width or census fails closed. The source census includes archive state, but embed leases are not archive coordination. Synthetic two-engine regressions cover preservation refusals, real imported-image migration, same-target companion preservation, retarget/first-clear refusal and fail-closed metadata. Completion counts remain archive-visible; refusal never restores a source automatically.
- `src/core/embedding-migration-budget.ts` — finite authorization in the existing migration marker. Each provider attempt reserves its maximum input price under the acquired leases and a `FOR UPDATE` on the marker row, and records a pending entry keyed by attempt id; `settle(usage)` takes the same lock and replaces the reservation with the reported usage (refund or overshoot). Idempotent per (`authorization_generation`, attempt id): a repeated or stale-generation settle is a no-op, so a crash before settlement keeps the maximum. Missing usage keeps the maximum. Usage above the reservation debits actual, adds `overshoot_usd` and sets `halted`, which refuses further dispatch until an explicit `--max-cost-usd` renewal. `authorizeMigrationBudget(..., worstCase)` throws `MigrationBudgetRefusal` (`embedding_budget_below_worst_case`, with cap, worst case, retained debits, the filled `--max-cost-usd` command and the `write-refusals.md` anchor) before writing any state when the cap is below debits + worst case. Refusal copy prints the operator's cap, never a remainder. Resume preserves every debit; unknown prices or missing input bounds refuse. Marker corruption cannot erase a versioned authorization. Only an explicitly reauthorized legacy marker without authorization fields can be replaced.
- `src/core/embedding-migration-worst-case.ts` — `planMigrationWorstCase(engine, plan, { rerankerModel })`: Σ per-request maximum input from `embed-batch-plan.ts` over what the run sends (target probe, the drain's two probes, stale chunks per page (including content drift: a stored text hash that no longer matches) split by `healOversizedChunks` at the target chunk size over the complete page (a split re-indexes siblings, so every healed chunk of that page counts) and wrapped with `wrapChunkTextsForStoredMode`, the chunks projection recovery and the chunkless heal will create — replayed through `readProjectionSnapshot` + `preparePageProjection` at the current chunk size then the target-size heal, and directly at the target size, keeping the larger ceiling, replacing those pages' existing chunks — stale facts in 100-row per-source batches, three smoke-check queries, the reranker probe when switching), priced with operator overrides. `usd` is null only when the embedding model is unpriced; an unpriced reranker lands in `unpriced_models` and the embedding bound is still enforced. Owns the migration and reranker probe texts. Computed at plan time for the printed estimate and again under the migration locks for the refusal.

- `src/core/embed-retry.ts` — embed retry/backoff primitives + the title-tier restamp helper. An `EmbeddingZeroNormError` (#4616) is never retried or classified transient; `embedBatchKeepingUsable` returns the usable vectors of a partially refused batch with the refusal, and still throws when nothing is usable. It stays in core because `src/core/import-file.ts` and `src/core/embed-stale.ts` consume these (a core→commands import would make every import-file consumer eagerly load the embed COMMAND module — one value import away from a real ESM cycle). `embedBatchWithBackoff` wraps `embedBatch` with rate-limit-aware retry: detects 429s via the wrapped error's `cause.status` (message-match fallback), also retries transient gateway 502/503/504, parses provider retry-delay hints, jitters ±30% so concurrent workers don't resynchronize, passes `maxRetries: 0` through so the AI SDK's own retry stack doesn't multiply attempts, and threads an external AbortSignal into both the sleep and the in-flight HTTP call. `restampIfDemotedToTitleTier` restamps a `per_chunk_synopsis` page's CR state to `'title'` after a plain re-embed so `contextual_retrieval_mode` keeps describing the vectors actually in the column (the reindex sweep restores the synopsis tier later). `src/commands/embed.ts` re-exports everything here (façade rule) so import sites and tests never chase the peel.

- `src/core/embedding-state.ts` — #6696 B3 derived embedding state: every chunk, and every live page with no chunk row, in one of `embedded | pending | keyword_only | quarantined | empty | deleted_page_chunks | chunkless_healable` against the ACTIVE embedding column (no stored status). - `src/core/embed-stale.ts` — source-wide stale embedding and explicit-page completion keep vector installation, complete-provenance signature checks and title-tier demotion in one page-guarded transaction. The three `src/commands/embed.ts` paths use the same transaction boundary; providers run before it. Standalone/background projection recovery preserves NULL-signature grandfathering and existing stale eligibility; the job's deadline, abort signal and source lease fence recovery, invalidation and publication. Oversized-chunk healing checks ownership and stop conditions before and after its transaction, rolling back prepared changes on loss. The restamp always uses the captured page metadata, so a later same-revision contextual rebuild cannot retain its vectors while an older completion overwrites its mode or corpus generation. `persistence/effects.ts` also retains this atomic completion boundary. `test/embedding-completion-atomic.serial.test.ts` exercises all five completion paths; `test/e2e/migration-wave-healing-fence.test.ts` pins healing rollback on both engines. #5902: without an explicit `concurrency`, `embedStaleForSource` (the unpaced `embed-backfill` job and the remediation embed step) runs `resolveStaleEmbedConcurrency` workers from `src/core/embed-concurrency.ts`: `min(20, max(1, floor(poolMax/2)))` of the engine's real pool (`getPoolDiagnostics().poolMax`, a worker's instance pool included), 20 without a pool; an explicit `GBRAIN_EMBED_CONCURRENCY` keeps the full-pool clamp. Pinned by `test/embed-stale-pool-default.test.ts` + `test/e2e/embed-stale-pool-default-postgres.test.ts`. Remaining work is judged by the chunk gap alone (NULL vectors in the active column, under the same body-generation and large-page budget gates as `listStaleChunks`), split by the retry ledger into eligible, backoff-deferred and quarantined (`getEmbedFailureSummary`, with `earliest_retry_at`). Once the maintenance steps (readiness, signature and content-drift invalidation) have run, a gap that is only deferred or quarantined (and nothing blocked) ends the drain as `deferred`: not success, not an ordinary failure, and no provider probe is spent on it; the `embed-backfill` handler returns status `deferred` with the earliest retry time or the manual-action hint. Every persistence transaction is fenced in the order ownership, then signal/deadline, with a last stop check right before COMMIT; lease loss stays a `LockStolenError`, recognised from the caught error itself and, failing that, from the stop signal's reason (the owner's `assertOwned` aborts with it before throwing; a runtime can deliver an abort with no reason, so the signal alone is never trusted): `embed-stale.ts` re-raises it from its signature-invalidation, content-drift-invalidation, heal, slice, stamp and restamp catches and after the worker join, and `commands/embed.ts` from its content-drift-invalidation, heal, slice, stamp and restamp catches, instead of mapping the stop to an abort (plain stop checks elsewhere only return, so a caller that must never see lease loss as an abort relies on the handler check below), the `embed --stale` worker pool treats it as run-global (like a config fault) instead of absorbing it as one page's failure, and the `embed-backfill` handler records the loss in its own `assertOwned` (before aborting the drain) and checks that record, not the signal's reason, before it maps `result.aborted` to `status:'aborted'`. Only a genuinely fired signal or reached deadline maps to `aborted`. Cancellation discards the whole in-flight slice (vectors already computed inside it included); earlier slices stay committed. Both slice drains (`embedStaleForSource` and `embed --stale`) embed a segmented page through upstream's segmented path first, meter each page's batch once with `meterPageBatch` (only the batch's rows, so chunks the retry ledger backs off or quarantines are never re-admitted; a held page waits; a capped page embeds only its granted chunks) and settle that grant after the slices (spent once any provider call returned, even if its slice then failed to commit; `test/embed-page-cap.serial.test.ts`), hand the first slice failure to `healAndReportOverLength` after the loop, and `embed --stale` books every key, early exits included, into `StaleChunkProgress`. The page signature stamp treats a NULL `embedding_input_hash` as current input only on pages without a contextual-retrieval mode (the `projections.ts` retention rule). Pinned by `test/embed-stale-deferred.test.ts`. A provider response that does not line up with the request (wrong vector count or width, `EmbeddingResponseShapeError`) is a per-item provider failure, not a config fault: the call's chunks are ledgered (`provider_other`) and bisected down to the offender while later pages keep embedding, as upstream does (`test/embed-malformed-response.serial.test.ts`, drives the real gateway; the invalid-input bisection treats a malformed sub-request response the same way and still stops on a real config fault, `test/embed-malformed-response-bisect.test.ts`). Run-global stops (a real config fault such as rejected credentials, or a must-abort budget or spend-group refusal) are returned as the slice's fatal error and rethrown; `classifyEmbedFailure` marks them `fatal`, so they never enter the retry ledger and a raised cap re-runs the same chunks immediately. Callers that must keep going past a provider-wide fault decide that themselves: `executeMigrationFlow` reports it as `incomplete` + `stopped_reason`, and the remediation embedding pass leaves the source pending (`stopped`). Wave B: a segmented page is embedded by `page-body/segmented-embedding.ts` (vector-less live rows by chunk_index keyset with the title and plain tier, metered per page, installed by chunk_index and exact text onto rows still in the live generation; never the body or every chunk), from here, `gbrain embed` and the post-commit embedding effect (`data.occurrence_ids` limits an append's effect to the new occurrences).
- `src/core/content-drift-sweep.ts` — the content-drift sweep (#4246) as a resumable pass: `runContentDriftSweep(engine, { sourceId?, signal?, deadline?, stopped?, assertOwned?, timeBudgetMs?, batchRows? })` runs `engine-sql/chunks.ts` `invalidateContentDriftBatch` (5,000 chunk rows past the cursor in id order, bounded before any md5) one transaction per batch, committing the cursor in config row `embed.content_drift_sweep.<column>.<all|source:id>` with the batch under a `FOR UPDATE` lock on that row, so concurrent runs share one pass. - `src/core/page-embedding-lease.ts` — one provider call per chunk content version (gbrain-evals#180, N14). Every path that embeds a page's vector-less chunks holds the page's embedding lease from reading which chunks lack a vector through its install: the post-write embedding effect (`persistence/effects.ts`, inline and segmented), the `gbrain embed --stale` drain (`src/commands/embed.ts`), `embedStaleForSource` and `embedStalePages` (`embed-stale.ts`), and every segmented install (`embedSegmentedRows` in `page-body/segmented-embedding.ts`). `acquirePageEmbeddingLease` takes a `gbrain_cycle_locks` row `embed-page:<page id>` with plain statements (TTL 2 minutes, refreshed every 30 s while held, no process-liveness takeover), waiting with backoff while another path holds it; an effect renews its claim in `whileWaiting`. The wait is bounded by the caller's `deadline` (`embedStaleForSource` passes its drain deadline) or one TTL, and then returns a busy lease (`{ busy: true }`): drains skip the page without counting a failure, the effect and the segmented effect throw `pageEmbeddingLeaseUnavailable` (`lock_busy`, retried with backoff), and `embedSegmentedPage` stops with `stopped: 'busy'`. A held lease's `assertHeld(tx)` renews the row inside every install transaction and throws `lock_busy` when it matches no row (the lease expired and another path took or deleted it), so a holder that stalled past the TTL installs nothing; a background refresh that matches no row marks the lease lost the same way. `embedStalePages` looks the page id up first and reads its snapshot under the lease. Callers bind it with `await using`, so leaving the scope releases it, error paths included; each release also deletes expired `embed-page:` rows (a crashed holder's), which keeps doctor `stale_locks` from listing them past the next embed. `NOT_PAGE_EMBEDDING_LEASE` (on `PAGE_EMBEDDING_LEASE_PREFIX`) keeps these rows, live or expired, out of activation's legacy-lock inspection (`persistence/legacy-locks.ts`), deactivation's lease blockers and shared-skill activation's quiescence check: a lease dedupes provider calls and guards vector installs that ran unleased before it, its holders run inside a lock, job lease or effect claim those checks already see, and a crashed holder's expired row must not block them (the writer admin fingerprint in `admin-intent.ts` skips them too). The holder then keeps only the chunks still without a vector (inline: `stillPendingChunks` over the fresh `getChunks` read; segmented: `vectorlessChunkIndexes`), so a drain whose listing predates an effect's install sends nothing for them. `pageEmbeddingLeaseProbe` (`contended`, `waitBoundMs`) is the test seam. Forced probes (effect first on a segmented page after `append_page`, drain first on an inline page; both engines): `test/embed-once-per-content-version.serial.test.ts`; bounded wait, lost lease, snapshot under the lease, expired-row sweep and release on throw (both engines): `test/page-embedding-lease.serial.test.ts`.

- `src/core/embed-budget-stop.ts` — the loud time-budget stop for `gbrain embed --stale`. `noteEmbedBudgetStop(engine, result, {sourceId, signature, includeNullSignature, skip})` counts the stale chunks left (same predicate as the catch-up remaining count) and, when any remain, sets `reason: 'time_budget'`, `remaining_stale` and `resume_command` (`gbrain embed --stale --catch-up [--source X] [--include-null-signature]`) on the result; `skip` covers dry runs, `--catch-up` and caller aborts. `embedBudgetStopVerdict(result)` is the stdout verdict `runEmbed` prints; `src/cli/commands/embed.ts` maps the reason to `BUDGET_STOP_EXIT_CODE` (failures still win with 1).
