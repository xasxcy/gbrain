- `src/core/embed-stall.ts` — progress-keyed stall watchdog for embed drains (mirror of sync's stall watchdog; bounds embed drains that hang without a pinned root cause). Two clocks, one trigger: LIVENESS ticks via `noteEmbedApiResponse()` on EVERY settled embed API attempt — success, error, or retry (hooked in `embed-retry.ts:embedBatchWithBackoff`; diagnostic only, distinguishes "fully wedged" from "live but failing" in the abort message, scoped to the armed run); the TRIGGER is no SUCCESSFUL forward progress (`readProgress()`, wired to chunks embedded) for `GBRAIN_EMBED_STALL_ABORT_SECONDS` (env-only knob; default 900 via `DEFAULT_EMBED_STALL_ABORT_SEC`, `<= 0` disables, garbage falls back to default) — a retry storm that never lands a chunk trips it BY DESIGN. A stall produces an ERROR RESULT (`reason: 'stall_timeout'`), never a `process.exit`: only the CLI wrapper (`src/commands/embed.ts:runEmbed`) maps it to a non-zero exit, and minion handlers and the cycle's embed phase (`cycle.ts:runPhaseEmbed`) convert it to a failure via `assertEmbedNotStalled`. The abort path runs an idempotent, deadline-bounded cleanup (`EMBED_STALL_CLEANUP_DEADLINE_MS`) that releases only the run's self-acquired single-flight locks and banks partial progress, so the next run resumes cleanly. The check interval is deliberately NOT unref'd — for non-single-flight callers it can be the only handle keeping a lost-promise hang loud; `stop()` clears it on every normal path. Pinned by `test/embed-stall.test.ts`.

- `src/core/embedding-input-limit.ts` — per-model embedding INPUT token caps. Some hosted encoders reject any single input over a hard per-input limit far below their batch budget (a 512-token model would otherwise leave ~35% of a typical vault's chunks permanently unembeddable, re-failing every sweep). `resolveMaxChunkTokens(env?)` resolves the effective chunk-token cap for the ACTIVE embedding model so the chunkers SPLIT (never truncate) at a size the model accepts: `GBRAIN_MAX_CHUNK_TOKENS` env (escape hatch for models not in a recipe; warn-once per distinct invalid value) → recipe per-model `max_input_tokens` × `EMBED_INPUT_SAFETY` (0.6 — covers the cl100k-based `estimateEmbedTokens` overestimate vs BERT-wordpiece tokenizer mismatch) → `DEFAULT_MAX_CHUNK_TOKENS` (2000 for every other provider). `MIN_CHUNK_TOKENS` floor of 64 so a tiny declared limit can't produce confetti chunks; fail-open on any resolver error (a resolver bug must never change chunking for unaffected installs). `maxInputTokensForModel(recipe, modelId)` mirrors `model_dims`' case-fold lookup rule (exact match first, then case-insensitive scan). Consumed at `import-file.ts`'s chunk step. Pinned by `test/embedding-input-limit.test.ts`. Declared limits ([R13] audit, PR #5922): NVIDIA `nvidia/nv-embedqa-e5-v5` 512; DashScope `text-embedding-v1`/`v2` 2048, `v3` 8192; Google `gemini-embedding-001` 2048 (the endpoint truncates silently past it); Zhipu `embedding-2` 512, `embedding-3` 3072; OpenAI `text-embedding-3-*` 8191 and Mistral `mistral-embed` 8192 (above the default, so no chunking change). Pinned by `test/embedding-input-limit-hosted-caps.test.ts`. **Learned caps** (`learnChunkCap` / `learnedChunkCap` / `_resetLearnedChunkCapsForTest`): a process-lifetime per-`provider:model` chunk cap that `src/core/embed-overlength-heal.ts` derives from a provider's single-input over-length rejection when the model declares nothing; `resolveMaxChunkTokens` applies it after the env override and the recipe declaration (both win over it), clamped to the same floor/ceiling.

- `src/core/embedding-invalidation.ts` — signature-truth guards shared by migration and embed paths, using identical SQL on both engines. `invalidateStaleSignatureEmbeddingsGuarded(engine, {signature, sourceId?, includeNullSignature?})` adds the stale selectors' embed-skip and projection-seal fences to raw engine invalidation. It runs as one statement pair per window of `SIGNATURE_INVALIDATION_PAGE_BATCH` (1000) page ids inside one transaction, so a full-corpus model swap on a large brain stays inside the statement timeout (#7148; Postgres proof in `test/e2e/stale-signature-invalidation-postgres.test.ts`). `hasSignatureDrift` is the embed paths' page-first pre-check: one EXISTS instead of two corpus-wide counts, so a healthy brain never reads `content_chunks` for it and a drifted brain is never counted before the probe. Current model/hash/width chunks survive interrupted batches; fully current active pages can be restamped without another embedding call. Input provenance follows `page-state/projections.ts` (#5553): a current-space vector with a NULL `embedding_input_hash` survives (and its page is restamped) only on a page without a contextual-retrieval mode; on a page whose mode is set (including `none`) it is nulled, re-embedded by the ordinary drain and then stamped by the strict stamp, never kept and never stamped by the invalidation. `currentInputChunkPredicate` is that rule, shared with `stampIfPageProvenanceComplete` and the drift and restamp-only counters. A fallback-truncated vector is not an unknown input: the installer records a distinct, non-NULL truncation provenance (`truncatedEmbeddingInputHash` in `embedding-input-hash.ts`: separate domain tag, truncation length and the digest of the text actually embedded, built with the same ctx, tier and wrapping as the full-input hash), so the strict stamp and the invalidation accept it, the next drain neither probes nor nulls it, and it never equals the full input's hash. It is not in `acceptedEmbeddingInputHashes`, so a projection rebuild (page content, chunker or indexing-context change) nulls it and re-embeds the chunk, which gives the provider another chance at the full input. Pinned by `test/e2e/embed-stale-null-hash-reembed.test.ts` (invalidate, re-embed, stamp, then a no-op drain without a probe, on both engines) and `test/embedding-signature-stale.test.ts`. Source `FOR SHARE` locks precede mutation in short transactions, serializing both signature writes, raw engine signature/content-drift invalidation, false-stamp clearing and final reconciliation against archive. Archived vectors and page signatures are never mutated. The shared `falseStampPageWhere` and `countFalseStampedChunks` remain archive-visible for retention, plan and completion diagnostics; only the clearing write is fenced. Bare provider-less model aliases retain their existing exemption. Provider dispatch and completion smoke run outside source locks and revalidate live, safe snapshots before sending text. Pinned by `test/embedding-migration.test.ts` and the shared `test/embedding-recovery.serial.test.ts` suite: PGLite runs in the serial lane, while `test/e2e/embedding-recovery-parity.test.ts` selects PostgreSQL.

- `src/core/llm-json.ts` — tolerant JSON extraction from LLM output. `parseLlmJson<T>(raw, {array?})` walks a strategy ladder (strip ```json fences → direct parse → first `{...}`/`[...]` substring; when the fenced extract fails, the same parses retry from the opening fence, or on the whole text when the fence sat inside a JSON string, so a quoted ``` cannot truncate the payload), then — only after the raw parse has failed — retries the same ladder with reasoning blocks stripped, so a payload that parses raw is untouched and a payload legitimately containing `<think>` is unaffected; returns null on any failure (adversarial throws swallowed). Exports `stripReasoningBlocks(raw)`: removes closed `<think>…</think>` pairs AND a truncated never-closed `<think>` tail (output-budget exhaustion) — reasoning models draft their JSON inside the think block, which defeats the greedy first-to-last-brace substring scan. Exports `matchingCloseBracket(text, openAt = 0)`: the index of the bracket closing the array/object that opens at `text[openAt]` (counts the opener's own kind, skips string literals whole including escapes; -1 when `text[openAt]` is not a bracket or the value never closes), which the chronicle judge, propose_takes and extract_atoms recovery paths use so a trailing `[Source: X]` citation cannot hijack the slice. `src/core/facts/extract.ts`'s hand-rolled `parseExtractorJsonDetailed` applies the same raw-first fallback ladder with the shared `stripReasoningBlocks`.

- `src/core/post-upgrade-reembed.ts` — Pure functions backing the `gbrain upgrade` chunker-bump cost prompt. `computeReembedEstimate(engine, model)` queries real SQL (`COUNT(*)` + `COALESCE(SUM(LENGTH(compiled_truth)) + SUM(LENGTH(timeline)), 0)`) on `pages WHERE chunker_version < MARKDOWN_CHUNKER_VERSION`. `formatReembedPrompt(est)` is the stderr-line formatter (count, model, cost estimate when priced). `runPostUpgradeReembedPrompt(engine, model, opts)` re-embeds only on consent: a TTY operator must answer `y` to `[chunker-bump] Re-embed now? [y/N]`; the default, EOF and every non-TTY run decline and print `REEMBED_DEFERRED_HINT` (`gbrain reindex --markdown`, or `gbrain repair safe-chunks --apply --no-embed` then `gbrain embed --stale`), so an unattended upgrade never spends. Reasons: `no_pending`, `bypassed_no_reembed`, `consent_required`, `tty_declined`, `tty_consented`. `GBRAIN_NO_REEMBED=1` skips the prompt with a doctor-warning marker. `opts.confirm` and `opts.isTTY` are test seams.

- `src/core/schema-embedded.generated.ts` — AUTO-GENERATED from schema.sql by `scripts/build-schema.ts` (run `bun run build:schema`, which also regenerates schema.sql's fragment regions and the PGLite template `src/core/pglite-schema.generated.ts`, exposed through the `src/core/pglite-schema.ts` façade; canonical-source graph in `docs/ENGINES.md#canonical-schema-sources`; the `.generated.ts` suffix exempts it from the module-size ratchet's new-file cap, per the guard's generated-file carve-out)

- `src/core/spend-log.ts` — per-OAuth-client paid-API spend tracking against the `mcp_spend_log` table. `checkBudget(engine, clientId, capCents)` is the pre-flight gate; throws `BudgetExceededError` when today's spend has hit the cap. `recordSpend(engine, entry)` is best-effort post-call. UTC day-aligned aggregation so caps roll over deterministically regardless of server timezone. Local CLI callers (no clientId) bypass the gate; brains without the table fail open to spend=0. `VOYAGE_MULTIMODAL_3_PER_IMAGE_CENTS` = 0.12 cents per image embed.

- `src/core/spend-posture.ts` — spend-control surface. `resolveSpendPosture(engine): 'gated'|'tokenmax'` (DB-plane `spend.posture`, fail-open `gated`); `tokenmax` makes every cost gate informational across sync/reindex/enrich/onboard (spend still ledgered — removes the ceiling, not the accounting). `parseUsdLimit(raw, def, {allowZero?})` accepts `off`/`unlimited`/`none` → `Infinity`; `formatUsdLimit(n)` renders `Infinity` as the string `'unlimited'` (never raw — `JSON.stringify(Infinity)` is `null`); `usdLimitToCap(n)` maps `Infinity` → `undefined` at the BudgetTracker boundary so ledger rows never serialize null. `normalizeSpendPosture`/`isValidSpendPosture` back the `config set` validation. Doc: `docs/operations/spend-controls.md`. Pinned by `test/sync-cost-preview.test.ts` + `test/spend-off-switch.test.ts`.

- `src/core/transcription.ts` — Audio transcription: Groq Whisper (default), OpenAI fallback, ffmpeg segmentation for >25MB. Each provider request routes through `invokeAI` with kind `transcription`, so admission guards and invocation observers see it.
